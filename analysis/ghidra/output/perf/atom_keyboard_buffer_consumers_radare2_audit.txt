Observed contracts
==================
0x00A237B0 takes the input owner in ECX and returns with plain RET. If the
keyboard at owner+0x2C exists, it calls its vtable+0x28 with size 20,
output NULL, requested count 0xFFFFFFFF, flags zero. This is the documented
GetDeviceData flush shape. The HRESULT and resulting count are not tested.

0x00A23820 takes the input owner in ECX and one stack output-pointer argument.
It requests one 20-byte event, flags zero, through the same device slot at
0x00A2385E. At 0x00A23860 it tests EAX and rejects every nonzero result,
including DI_BUFFEROVERFLOW (1). On zero HRESULT and nonzero output count,
it writes the event offset to the caller pointer and returns 1 for a press
(data bit 0x80 set), 2 for a release. Rejected/empty reads return zero without
writing the caller's output. RET 4 confirms one stack argument.

0x00A237F0 forwards its output argument to 0x00A23820 and returns true only
for result 1. This establishes one direct native consumer; complete caller
coverage, invocation frequency, focus-transition order, and runtime incidence
are not established by this excerpt.

Atom source comparison
======================
atom/src/input/buffered.rs consume_events removes mirror entries before the
provider call and keeps mirror.overflowed until mirror.len reaches zero.
merged_result returns 1 whenever mirror overflow remains and the provider
has not failed. Thus, conditional on an overflowed mirror and successful
one-event reads by 0x00A23820, those reads consume entries but return zero to
the caller while overflow is reported. This is a source/binary consequence,
not a reproduced runtime failure and not evidence of mouse stutter.

Acquisition status cannot be recovered from Atom's outer void sampler result.
The existing immediate-state audit records native Acquire before the
post-sample GetDeviceData capture. Atom's focus epoch comes from sampled
foreground-window equality, not a device acquisition notification. No new
hook or mirror-discard policy is authorized by this evidence.
