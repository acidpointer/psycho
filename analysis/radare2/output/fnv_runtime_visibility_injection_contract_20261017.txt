Scene graph occluder list
  0x00B5AC90 activation pass:
    esi = object returned by 0x00450B80(0); esi+0x1E0 is the scene graph
    edi = scene_graph+8 list head
    for each list node esi = node+8 (the BSOcclusionPlane):
      al = 0x00C33CF0(esi, 0, temp)
      al = 0x00C358A0(esi, camera_xyz) AND previous
      edx = (al == 0) ? 2 : 1
      node+0x40 = edx
    So +0x40 == 1 means admitted/active for the current camera; +0x40 == 2
    is not tested by the pair loop.
  0x00B5BBE0 bound pair loop:
    for each admitted bound:
      edi = scenario accumulator/list context
      esi = scene_graph+8 list head
      for each node with [node+0x40] == 1:
        call 0x00C47150(bound, ..., node, ...)
        if result == 0 (rejection), stop
  0x00C47150 pair predicate:
    uses 0x0045C620 to initialize a local 100-byte frustum;
    calls 0x00C33870 to obtain camera-dependent planes;
    calls shape virtual slot +0xA0 for a complete containment predicate;
    on containment sets shape+0x08 = 2 and returns 0.
  0x00C33870 plane cache:
    dirty byte player/occluder+0xE5; cached camera XYZ at +0xD8/+0xDC/+0xE0;
    on clean+equal copies 25 DWORDs (100 bytes) from +0x44 to the caller.
  0x00C35C10 corner builder:
    reads size at +0x14 and +0x18; 0x4B4500(matrix, (sizeX,0,0)) and
    0x4B4500(matrix, (0,0,sizeY)) produce the two in-plane half-axis vectors;
    the four corners are position(+0x08) +/- the first vector +/- the second.
    This establishes a local XZ rectangle with a local Y normal and proves the
    two size fields are half-extents. Generated matrices must store columns
    (tangent A, normal, tangent B); the earlier (tangent A, tangent B, normal)
    order put the normal in local Z and made the plane edge-on.
  0x4B4500(ecx=matrix, v):
    computes (row0.v, row1.v, row2.v) and stores them through 0x00416870, a
    plain row-major M*v multiply. The matrix at plane+0x1C is row-major.

XOCP payload semantics (closed)
  - FO3_Optimization.esm XOCP payloads are 36 bytes (nine little-endian
    floats). Example ref 0x11012837:
      6e8c8944 8fd7ea43 e2eb0845 a4868744 cc5dff45 0000803f
      00000000 00000000 db0fc93f
  - The reference XOCP handler 0x0041617A reads the 36 bytes, allocates a
    0xFC BSOcclusionPlane with 0xAA13E0, constructs it with 0x00C335D0, then:
      0x00416A30(plane, &payload[0]) copies float 0 and 1 to plane+0x14 and
                  plane+0x18 => native half-extents size X and size Y.
      0x004169F0(plane, &payload[8]) copies floats 2..4 to plane+0x08
                  => position X/Y/Z.
      0x004168A0(matrix, angle, axisX, axisY, axisZ) builds the rotation:
                  the caller passes payload floats 7 (angle), 5 (axisX),
                  6 (axisY), 8 (axisZ) in that order.
      0x00416A70(plane, matrix) copies the 9 matrix floats to plane+0x1C.
  - Closed field order:
      0 sizeX, 1 sizeY, 2 posX, 3 posY, 4 posZ,
      5 axisX, 6 axisY, 7 angle, 8 axisZ.
    Axis-angle is the generator contract. Example `(0,0,1,1.5708)` is a
    90-degree rotation about +Z.

Orientation note
  0x00C358A0 returns 1 immediately when plane+0xEA is nonzero. 0x00C335D0 and
  0x004A5FF0 both set +0xEA = 1. 0x00C33870 builds the camera-dependent
  frustum from the camera and the four corners from 0x00C35C10 and has separate
  camera-side branches. A plane behaves as a window; the occluded volume is the
  camera-through-rectangle pyramid. The stored normal sign does not select the
  side in those two branches. The owner's visual check remains required.

Collector admission and timing (2026-10-17)
  - The reference list is the cell's own `objectList`; a reference with a
    non-null `parentCell` that differs is skipped, and a null parent is
    tolerated while the cell is still attaching references.
  - A transparent or skinned geometry is skipped individually, so one window or
    decal cannot discard a whole building.
  - The +0x9C pointer is only trusted as an alpha property when
    `[[+0x9C]] == 0x0109B4F4` (the NiAlphaProperty vtable). Otherwise the
    geometry is admitted, so a wrong or shifted offset cannot yield zero
    candidates.
  - Static content is gated by base type 0x20 (TESObjectSTAT) or 0x21
    (BGSStaticCollection); 0x22 (BGSMovableStatic) is excluded because its 3D
    can move after the planes are created.
  - Planes are derived from one world-space box per opaque, unskinned geometry
    (never merged across an object), with each face shrunk to half extent
    (`PLANE_SHRINK = 0.5`) so the camera-through-rectangle cone stays narrow.
    A triangle-silhouette extraction was prototyped and is parked until its
    mesh list is verified in game.
  - A cell/scene change retries a bounded settle window (up to 5 retries, 20
    frames apart) because the first frame can run before the cell's references
    and their 3D are attached. A retry with an unchanged plane-set signature
    keeps the existing planes, and the window stops early once two consecutive
    passes agree (`SETTLE_STABLE_PASSES`). Only a stable set is cached, so an
    incomplete first pass is never reused on a revisit.
Per-frame, cache and debug findings (2026-10-18)
  - Owner log analysis: every cell change produced six full scans with
    `cached=false` and constant `raw`/`faces`, i.e. the set was regenerated six
    times and never cached. The settle signature was never stabilizing and the
    cache was never written, so every visit paid the full walk and the occluder
    list was rebuilt repeatedly (the likely source of the terrain popping).
    Fixes: the cache is written on every generated pass; the settle signature
    is quantized (quarter-unit positions) and hashed with `FxHasher`; the
    window stops after two identical passes.
  - The steady-state frame compares the scene and cell pointers directly and
    only computes the cell identity hash when a pointer changes, so no hashing
    runs on a normal frame.
  - The vertex AABB reduction uses four-wide SIMD via the `wide` crate
    (SSE/AVX/NEON with a scalar fallback).
  - Debug view: `PsychoEngineFixes_QueryOcclusionDebug` returns a flat float
    frame (observer plus one rectangle per plane, with half-size, normal,
    tangent and bitangent). The helper's `PsychoOcclusionDebug` command toggles
    it and opens the dashboard, which draws a top-down wireframe of the
    rectangles via a new `psycho-imgui` foreground-line primitive. The
    dashboard's navigation menu also carries an "Occlusion debug" checkbox for
    the same toggle, and once enabled the overlay renders on every present even
    after the dashboard window is closed. The command must not call `cmd.print`:
    `Console::print` runs `print "..."` through `RunScriptLine`, re-entering
    xNVSE's non-re-entrant parser from inside the handler; that produced a real
    2026-10-18 "Mismatched quotes. String literal was not closed." error on
    `psoccl`. The handler logs instead.
  - The `[OCCLUSION_PLANES] scan` debug counters (refs, parent_mismatch,
    not_stat, render_null, node_null, radius, geoms, skinned, alpha, no_mesh,
    triangles, clusters, cluster_area, coverage, size, distance, faces) are the
    runtime diagnostic when a cell yields too few candidates.

Persistent cache, mod binding and timing (2026-10-18)
  - DataHandler::Get() returns *(DataHandler**)0x011C3F2C (xNVSE GameData.cpp
    RUNTIME branch).
  - DataHandler::modList is at +0x210; its ModList starts with a
    tList<ModInfo> whose head node holds the first entry in `+0` and the next
    node in `+4`. ModInfo::name is char[0x104] at +0x20 and its embedded
    WIN32_FIND_DATA at +0x29C carries nFileSizeHigh at +0x2B8 and
    nFileSizeLow at +0x2BC (GameData.h). The cache header hashes the ordered
    name+size list, so a mod install, uninstall, reorder or in-place update
    changes the signature and discards the cache.
  - Each cached plane stores the base form's TESForm::refID (+0x0C) so it is
    bound to its source plugin.
  - The engine can clear scene_graph+8 on cell unload without changing the cell
    identity. A periodic presence check (every 30 frames) re-appends the cached
    planes when a tracked plane is missing; this is the fix for the "leave and
    come back" loss of planes and the extra work.
  - Vertices are transformed with the `wide` crate (portable SIMD over
    SSE/AVX/NEON with a scalar fallback) four at a time; the scalar tail is the
    existing single-point transform.

Unknowns left open by this capture
  - The exact 0x00C33870 camera-side branch signs were not reduced to a
    formula; the engine's axis-angle setters are used instead, and the Phase 1
    experiment confirms the behavior.
  - The scene graph +8 list's per-cell reset behavior for runtime additions was
    not proven; the runtime design scans for its own plane pointers and does not
    depend on the reset timing.
  - Whether OnFramePresent is quiescent relative to 0x00B5AC90/0x00B5BBE0 was
    not measured; the CellTransitionOrchestrator 0x008774A0 is the fallback.
  - The room-build entry point, rebuild trigger, and reference lifetime needed
    for runtime room injection were not closed.
  - The runtime collector's false-cull rate and performance impact were not
    measured; it is an unqualified heuristic on authored OBND bounds.
  - BGSStaticCollection and BGSMovableStatic bounds layouts were not verified,
    so only TESObjectSTAT is admitted to runtime collection.
