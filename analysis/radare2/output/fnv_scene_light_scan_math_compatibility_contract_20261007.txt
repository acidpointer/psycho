5. Executable leaf contracts

The actual bytes were extracted to /tmp as headerless inputs, mapped at the
native destination and fully disassembled with radare2 MCP:
psycho-scan-normalize-installed-leaf.bin
psycho-scan-vector_length-installed-leaf.bin
psycho-scan-vector_sqrt-installed-leaf.bin
These are copied DLL payloads, not reconstructed functions. Cached native
XREF annotations in raw leaf output are ignored; they are not references in
these headerless files.

Normalizer: reads/writes only the three float components [ECX + 0/4/8].
SSE XMM0/1 arithmetic; no calls, stack writes, node/scene reads or x87 traffic;
both branches return with plain RET.
Magnitude: reads only the three vector components. PUSH ECX reserves one
word below entry ESP; MOVSS writes that private word; FLD returns ST0;
POP ECX and RET restore the stack. No caller-frame or heap writes.
Vector sqrt: reads the scalar at [ESP+4]; FLD, FSQRT, RET; no memory writes.
All three have no external call or hidden cursor-memory access.

These instruction contracts establish that these exact leaves do not overwrite
the scan's carried cursor slots. They do NOT prove numeric identity with the
vanilla routines. A compatible scan must retain calls to the installed math
bodies and their existing results, rounding and exception behavior.

6. Scope and rejected leads

A bounded source search of directly spelled addresses inside the nine guarded
ranges found these three executable math writers in the available optimization
sources. This is not exhaustive coverage of computed writes or other mods.
The reference NVAC.cpp calls InlineFldz(0xB9D489), but InlineFldz itself has an
empty body at line 44 in this partial source. It is not evidence of a live
shadow-consumer patch and was rejected as a cause.
The earlier deployed getter/range/overlay investigation found no proven
Psycho-internal bad signature. Absence of such proof is not proof that every
other rejection condition is absent.

7. Bounded correction contract, not implementation or runtime acceptance

The implementation defect is vanilla-only admission of these math bodies.
A capability-based correction may accept vanilla or these exact verified
math implementations while preserving consumer windows, getter, property
iteration, captured providers, monotonic rejection, cursor ownership and
installed arithmetic. Unknown code still rejects. Do not identify a module,
depend on a version, learn arbitrary bytes, wildcard signatures, rewrite math,
patch another mod, reorder loaders or clear an existing rejection.
Alternate signatures must apply to initial preparation AND later qualification.
The native bytes beyond each copied leaf have not been replaced by this writer;
a full-range alternative must verify that tail rather than ignore it.
The existing score-reuse qualification does not guard these three scan-only
entries, so this specific conflict does not imply score-reuse rejection.

This research establishes a deterministic static incompatibility with a
configuration-selected installed writer. It does not establish the first
mismatch in the historical session, measure FPS, demonstrate live cursor
lifetime/thread exclusion or execute a corrected scan. No production edit,
release, packaging, deployment or commit is authorized by this evidence file.
