Direct binary evidence
======================

Input initialization @ 0x00A22660
---------------------------------

radare2 identifies one call from 0x0086C80C. The function invokes
DirectInput8Create, then CreateDevice with the GUID stored at 0x01100F84. The
GUID bytes begin with 61 2B 1D 6F and identify GUID_SysKeyboard
(Data1 0x6F1D2B61). The returned keyboard device is stored at owner offset
+0x2C.

The later device at owner offset +0x30 uses GUID_SysMouse and separate
cooperative-level sites at 0x00A229A9/0x00A229CB. Those mouse sites are outside
this feature and remain unchanged.

Flag decoding
-------------

DirectInput cooperative-level constants:

  DISCL_EXCLUSIVE     = 0x01
  DISCL_NONEXCLUSIVE  = 0x02
  DISCL_FOREGROUND    = 0x04
  DISCL_NOWINKEY      = 0x10

Therefore:

  0x16 = NONEXCLUSIVE | FOREGROUND | NOWINKEY
  0x15 = EXCLUSIVE    | FOREGROUND | NOWINKEY
  0x06 = NONEXCLUSIVE | FOREGROUND

Replacing only each PUSH imm8 operand with 0x06 preserves instruction size,
branching, stack layout, HWND selection, COM owner, this pointer, vtable slot,
and call ABI. Both native branches then retain foreground DirectInput keyboard
delivery without requesting exclusive or Windows-key suppression.

Display-mode independence
-------------------------

The branch selector is state within input initialization, not the engine's
bFull Screen mode selector at 0x00446E10. Neither branch reads the top-level or
renderer-child HWND globals used to distinguish native fullscreen from
windowed rendering. Both obtain the active HWND from USER32. The two-site
keyboard patch is therefore identical for native fullscreen, framed windowed,
and borderless windowed modes.

Cursor contract reused from established evidence
=================================================

Cursor confinement does not require a new engine address. It reuses the
audited top-level CreateWindowExA return at 0x0086AF48. Established evidence

Intervention contract
=====================

PROVEN:

- 0x00A22660 creates and configures the DirectInput keyboard device at +0x2C.
- 0x00A22782 and 0x00A227A1 are the two keyboard SetCooperativeLevel flag
  pushes, and both calls use GetActiveWindow and vtable +0x34.
- native flags 0x16 and 0x15 both include NOWINKEY; 0x15 is also exclusive.
- changing either instruction to PUSH 0x06 is size preserving and retains the
  shared foreground DirectInput ABI.
- keyboard setup does not depend on the engine display-mode selector.

IMPLEMENTATION DECISIONS DERIVED FROM THE PROOF:

- preflight the complete fixed control-flow span while accepting either native
  or already-replaced values at only the two owned immediates;
- patch both sites in one rollback-capable transaction, never one branch alone;
- leave the separate mouse device and its cooperative levels untouched;
- install during early core activation before engine input initialization;
- treat a fingerprint conflict as local unavailability and continue unrelated
  engine fixes.

RUNTIME OBSERVATION STILL REQUIRED:

- confirm Windows/Super, PrintScreen, and consumer/media commands reach the
  host on the supported Proton/Wine stack while normal Fallout keyboard input
  remains active in all three display modes.
